# Router view-transition recovery patch

The installed versions differ: `@tanstack/react-router` is **1.170.41** and
`@tanstack/router-core` is **1.171.34**. The maintained patch is
`patches/@tanstack+router-core+1.171.34.patch`, applied by the existing
`patch-package` postinstall. It is separate from the Redact patch.

A browser regression reproduced the failure before the patch: when
`document.startViewTransition` threw `InvalidStateError`, the URL changed to
pricing but home stayed visible, and the navigation produced an unhandled
rejection. The original frontend's scheduler recovers from that browser error.
This was not resolved by disabling transitions or replacing the browser API.

The patch fixes Router's transition entry point. It memoizes the update promise
before running the route commit. If the native API throws, or its update
lifecycle rejects without invoking the callback, Router runs that same update
once. A callback that already ran cannot be repeated. If the actual route commit
rejects, that original rejection still propagates. Rejections from the
animation-only `ready` and `finished` promises are consumed because skipping an
animation must not create an unrelated unhandled rejection.

Both ESM and CommonJS output and the TypeScript source are patched. Source maps
were regenerated by transpiling the modified source, mapping that output onto
the installed output with a source-aware edit map, and composing those maps.
They include the modified source rather than stale pre-patch source text.

Verification:

- Four focused Router tests cover rejection before callback, throw after
  callback, skipped lifecycle promises with a later callback, and preservation
  of the original asynchronous commit error. All pass.
- The shared motion-policy and memory-router tests cover original shell rules,
  initial load, focus invalidation, reduced motion, history, redirects and
  superseded loads. All pass.
- Three native Chromium browser tests pass: selective actual animation events
  and home entrance suppression; injected browser API failure still completing
  navigation; and a real delayed payload superseded without blank main or stale
  content. Logs: `/tmp/kody-motion-recovery-tests.log` and
  `/tmp/kody-motion-browser-fixed.log`.
- `patch-package` generated the diff against its clean package install.
  `git apply --check --reverse` succeeds on the patched checkout. A forward
  check against copies of the original five changed files also succeeds, without
  rewriting the active dependencies.

Application restoration uses supported Router subscriptions and `router.update`,
with the original pure motion policy shared by both frontends. The main element
again carries `view-transition-name: page`. Browser tests confirm `data-spa-nav`
suppresses the repeated homepage entrance under Redact.

This adds dependency maintenance cost. On a Router upgrade, check whether the
upstream release contains equivalent recovery and retire or rebase this patch,
then rerun these tests and the full validation gate. This is not a claim that
all historical scheduler behavior or every browser has been reproduced. The
patch does not add an application-owned transition queue, and rapid navigation
with Back, browser visibility changes and other engines remain useful follow-up
coverage.
